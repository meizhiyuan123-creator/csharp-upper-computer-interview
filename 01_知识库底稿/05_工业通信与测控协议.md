## 1. 工业上位机通过串口（RS485/RS232）或 TCP 与下位机/PLC 通信时，如何彻底解决粘包、半包与数据不完整问题？

- **题目标识**：`COMM-01`
- **重要程度**：⭐⭐⭐⭐⭐ (5星)
- **核心标签**：`通信` `串口RS485` `TCP` `粘包断包`

### 💡 30秒速记提纲（面试张口就来）
> 1. **定性**：底层通信（无论 TCP 流式传输还是串口缓冲区轮询读取）都是无边界的字节流（Stream），没有天然的“数据包”概念，粘包与半包是物理层与传输层的必然现象。
> 2. **核心解法**：设计**应用层协议定界机制**（定长法、特殊包头包尾法、或【帧头 + 长度域 + 数据载荷 + CRC校验 + 帧尾】结构）。
> 3. **工程落地**：上位机维护环形缓冲区或 `MemoryStream` 缓存，采用状态机解析：先找帧头，字节不足等下次，字节满足则校验 CRC，校验通过切分完整数据包并投递，校验失败滑移 1 字节重新寻头。

### 🔍 深入原理解析
### 1. 粘包与断包产生根因
- **粘包（多合一）**：下位机连续快速发送两帧（如 `AA 01 02 FF` 与 `AA 02 03 FF`），上位机单次 `SerialPort.Read` 一次性读出 8 字节。
- **半包（一拆多）**：下位机发出一帧 20 字节的数据，上位机串口缓冲区由于波特率与扫描周期差异，第一次读到 12 字节，第二次读到 8 字节。

### 2. 状态机分包算法标准流程
```
[接收字节] -> 追加到 Buffer 缓冲区
  └─> 检查缓冲区长度是否 >= 最小帧头长度
        ├─ 是 -> 扫描帧头 (例如 0x5A 0xA5)
        │          ├─ 找到帧头 -> 读取长度字段 L
        │          │                ├─ Buffer.Length >= L -> 提取该帧 -> 校验 CRC16
        │          │                │                            ├─ 成功 -> 触发 OnPacketReceived，从 Buffer 剔除这 L 字节
        │          │                │                            └─ 失败 -> 剔除帧头首字节，向后滑动 1 字节继续找
        │          │                └─ 字节数不足 L -> 退出等待下一次数据到来
        │          └─ 未找到帧头 -> 清理无用杂质字节
        └─ 否 -> 退出等待
```

### 🛠️ 上位机实战避坑（工程案例）
在 RS485 设备通信模块中，针对 Modbus-RTU 这种依赖无传输字符间隔（3.5个字符时间）判帧的协议，若波特率为 115200，3.5T 仅约 0.35ms，操作系统线程调度抖动极易导致半包。实战方案是结合协议长度预判与自实现滑动窗口环形缓冲区（RingBuffer），收到后先根据功能码（如 0x03 读保持寄存器其返回长度为 3 + 字节计数 + 2 字节 CRC）动态计算预期整包长度，配合 CRC16 校验，实现了千万次通信 0 粘包 0 误判。

### ⚠️ 常见连环追问
- Q: 为什么串口通信在大量干扰时不能只用 Try-Catch 忽略异常？（答：工业现场变频器或强电干扰会导致串行信号毛刺，丢弃会导致寄存器时序错乱，必须有 CRC 校验和重发机制）

## 2. Modbus-RTU 协议的帧结构是什么？PLC/从机响应超时的重发机制与多指令优先级队列如何设计？

- **题目标识**：`COMM-02`
- **重要程度**：⭐⭐⭐⭐⭐ (5星)
- **核心标签**：`通信` `Modbus-RTU` `CRC16` `指令队列与重连`

### 💡 30秒速记提纲（面试张口就来）
> 1. **帧结构**：【从机地址 1B】 + 【功能码 1B】 + 【数据段 N 字节】 + 【CRC16 校验低字节 + 高字节】。
> 2. **通信半双工特性**：RS485 是半双工总线，任何时刻只能有一台主机发起问询并等待单台从机应答，严禁多线程并发裸写串口，否则必然导致总线总线数据冲突乱码。
> 3. **架构解法**：设计**线程安全的单线程消费指令队列（Command Queue）**，支持优先级插队（如急停指令高优先级插队），结合 `CancellationTokenSource` 超时令牌控制单次等待（如 200ms），失败自动重发 3 次，连续多次超时触发状态机断线报警与重连。

### 🔍 深入原理解析
### 1. 常用功能码速记
- `0x01` / `0x02`：读线圈（Coil） / 读离散输入（Discrete Input）
- `0x03` / `0x04`：读保持寄存器（Holding Register） / 读输入寄存器（Input Register）
- `0x05` / `0x06`：写单个线圈 / 写单个保持寄存器
- `0x10` (16)：写多个保持寄存器（批量下发速度或参数常用）

### 2. 健壮的工控指令调度队列架构
```csharp
public class ModbusCommandChannel {
    // 基于优先级队列或双端队列
    private readonly PriorityQueue<ModbusCommand, int> _queue = new();
    private readonly SemaphoreSlim _lock = new(1, 1);

    public async Task ProcessQueueAsync(CancellationToken ct) {
        while (!ct.IsCancellationRequested) {
            var cmd = await DequeueNextAsync();
            for (int retry = 0; retry < 3; retry++) {
                await SendBytesAsync(cmd.RequestBytes);
                var (success, response) = await WaitForResponseAsync(cmd.TimeoutMs);
                if (success && VerifyCrc(response)) {
                    cmd.SetResult(response);
                    break;
                }
                if (retry == 2) cmd.SetException(new TimeoutException());
            }
        }
    }
}
```

### 🛠️ 上位机实战避坑（工程案例）
在科研医疗仪器上位机中，电机的实时速度采集属于常规周期性指令（低优先级），而用户的“急停按键”或“限位光电触发”属于紧急指令（高优先级）。指令队列支持优先级调度，当触发急停时立即将 0x06 写寄存器停止指令插入队首，在 20ms 内完成伺服停机，保障实验人机安全。

### ⚠️ 常见连环追问
- Q: CRC16 查表法和直接移位计算法哪个好？（答：查表法以 512 字节空间换时间，微秒级完成，工控高频通信首选查表法）
- Q: 断线重连时，串口 Port.Open 容易卡死几秒怎么办？（答：必须将重连逻辑完全移到后台 Task 执行，禁止在 UI 主线程直接调用 serialPort.Open()）

## 3. OPC UA 与传统 Modbus 相比有哪些核心优势？在上位机中如何实现节点数据订阅（Subscription）与值变化监听？

- **题目标识**：`COMM-03`
- **重要程度**：⭐⭐⭐⭐ (4星)
- **核心标签**：`通信` `OPC UA` `Modbus对比` `节点订阅`

### 💡 30秒速记提纲（面试张口就来）
> 1. **协议层级差异**：Modbus 是扁平寄存器地址（只有无含义的 40001 偏移），无数据类型语义；OPC UA 是面向对象的工业通信标准，支持自描述信息模型、命名空间、丰富数据类型与严密安全加密认证（X.509 证书）。
> 2. **通信模式跨越**：Modbus 只能由上位机不断低效轮询（Polling），占用总线带宽；OPC UA 支持**发布-订阅（Pub/Sub）机制**，仅在 PLC 变量发生变化时主动推送（Report by Exception）。
> 3. **C# 开发实现**：基于官方 `Opc.UaFx` 或 `Opc.Ua.Client` 库，建立 Session 会话后创建 `Subscription`，添加 `MonitoredItem` 监听指定 NodeId，挂载 `Notification` 事件实现无感知异步更新。

### 🔍 深入原理解析
### 1. 核心对比矩阵
| 维度 | Modbus-RTU / TCP | OPC UA |
| :--- | :--- | :--- |
| **数据模型** | 扁平寄存器（0/1/3/4区），无元数据 | 树状节点（NodeId）、对象、变量、方法、强类型 |
| **传输开销** | 必须定时轮询（大量重复读），总线负载重 | 变化推送（MonitoredItem），节省 80% 工业网络带宽 |
| **安全性** | 明文传输，无权限控制，易受攻击 | 支持 TLS/SSL 加密、数字签名、用户角色权限鉴权 |
| **跨平台** | 依赖串口或 Socket 报文解析 | 跨平台统一标准，原生支持 Linux/Windows/Docker |

### 🛠️ 上位机实战避坑（工程案例）
在多通道机电综合测控上位机中，设计了 Modbus + OPC UA 双层架构：底层小型自研控制器采用 Modbus-RTU 快速直连，厂区西门子 S7-1500 PLC 与环境智能网关通过 OPC UA 对接。通过订阅 PLC 的报警节点，当出现急停或过载时毫秒级收到推送并触发上位机联锁停机，无需上位机耗费 CPU 循环轮询。

### ⚠️ 常见连环追问
- Q: OPC UA 订阅的 PublishingInterval 和 SamplingInterval 有什么区别？（答：SamplingInterval 是服务器采样硬件寄存器的周期，PublishingInterval 是服务器向客户端批量推送更新包的周期）

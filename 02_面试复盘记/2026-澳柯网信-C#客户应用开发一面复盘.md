## 二、 核心追问满分标准回答示范

### 问：“封装过海康相机 SDK，如果要换成大华等其他品牌，软件如何适配？”

> 💡 **30秒结论话术**：  
> “在架构设计上，我遵循**依赖倒置原则（DIP）**，在上层业务与底层特定厂商 SDK 之间引入了**硬件抽象层（HAL，Hardware Abstraction Layer）**。上层业务代码只依赖统一的 `ICamera` 抽象接口，具体品牌驱动作为实现插件，通过依赖注入（DI）解耦，更换品牌时上层业务代码 0 修改。”

#### 展开架构细节（3步走）：
1. **统一能力契约（`ICamera` 接口）**：
   - 提取各工业相机厂商的公因子方法：`Open()`、`Close()`、`StartGrabbing()`、`StopGrabbing()`、`SetExposureTime()`、`SetGain()`、`TriggerSoftware()`；
   - 统一输出数据模型：定义不依赖任何厂商的 `CameraFrameReceivedEventArgs`，将各品牌私有图像结构统一转换为统一的内存指针、宽高、步长（Stride）与像素格式（PixelFormat）。
2. **多厂商实现与工厂封装**：
   - 分别编写 `HikCameraDriver : ICamera` 与 `DahuaCameraDriver : ICamera`；
   - 采用简单工厂或配置驱动，结合 DryIoc / MS.DI 注册：`services.AddKeyedSingleton<ICamera, DahuaCameraDriver>("Dahua")`。
3. **消除品牌特有差异的避坑点**：
   - **错误码与异常标准化**：各厂商 SDK 的错误码体系不同，驱动层将其统一包装为自定义的 `CameraDeviceException`；
   - **参数枚举映射**：触发模式、像素格式在内部维护映射字典（Dictionary），杜绝厂商专有枚举泄露至上层 ViewModel。

## 三、 面试试后评估与建议

1. **整体评价**：澳柯网信更关注软件工程的设计素养（抽象、分层、重构能力），而非纯底层硬件或死记硬背算法。
2. **后续复试建议**：
   - 深入理解跨平台桌面框架 **Avalonia**（跨 Windows/macOS/Linux）；
   - 了解现代桌面多进程架构与 IPC（如 **StreamJsonRpc / 命名管道**），展现解决大型客户端复杂架构的能力。
